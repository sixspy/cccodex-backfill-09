**回灌窗口 → 按日切片计划 → 重放落库 → 覆盖对账**

## backfill-09 · 日窗配额闸口

**主链**：出片 → 设额度 → 调度确认开闸 → 重放落库 → 对账复验。

- **超额落库选边：旁路凭证**。旁路配额账册（`quota_ledger`，每窗一行）原子改写剩余额度
  （`UPDATE ... WHERE quota-poured >= ?`），扣不动即整片拒灌，**超额行不进表**；
  未选库内硬闸（唯一索引核额度回冲突）一侧。
- **额度与已灌量同源**：同账册同行；目标表 `target_rows` 与账册同事务落库。
  复验发现账册 ≠ 目标表即**双账立刻拦**（409 + `双账拦截` 留证）。
- **调度确认开闸**：`BEGIN IMMEDIATE` 当场落成，两侧同时确认有锁串行、一成一冲突，
  不互相覆盖账册行；出错回短句（`闸口已开：GATE-xxxx` / `超配额拒灌：剩余X行，需Y行`）。
- **四处联查**：配额清单（亮超额拒灌芯片）/ 窗界详情（留证时间线）/
  闸口策略（亮闸口号）/ 对账回放台（复验超额行数）。
- **拒灌留证**：`quota_events` 本地库留证（开闸 / 拒灌 / 双账拦截 / 额度调整），
  页上拒灌芯片取自该表。
- **验收**：把额度打到零再开闸 → 重放必拒灌、芯片亮 → 目标表超额行数为零才过。

关键接口：`GET /api/quotas` · `POST /api/windows/{id}/quota` ·
`POST /api/windows/{id}/gate/confirm` · `GET /api/windows/{id}` ·
`GET /api/gate-policy` · `POST /api/coverage-reports`（复验）。
